# AI Prompt 模板变更日志

本文档记录 AI 提示词模板的每一次变更及原因，便于问题追溯和团队协作。

---

## [v3] 2026-04-07 - STAR法则 + 量化数据

### 实习经历 (internship)

**变更**：要求按照 STAR 法则输出，每句话必须有量化数据

**Prompt 片段**：
```
请按照STAR法则撰写实习经历的描述：
- S (情境)：项目背景或业务场景
- T (任务)：面临什么技术或业务挑战
- A (行动)：具体做了哪些工作，用了什么技术
- R (结果)：取得了什么量化成果（如性能提升%、用户增长、交付效率等）
```

**决策原因**：
- 用户反馈 AI 输出太空洞，没有实际帮助
- 简历内容需要具体、可量化才有说服力
- STAR 法则是业界标准的简历撰写方法

---

### 项目经历 (project)

**变更**：要求 STAR 法则 + 量化结果

**Prompt 片段**：
```
请按照STAR法则撰写项目经历的描述：
- R (结果)：取得了什么成果，尽量量化（如性能提升%、功能数量、用户量等）
```

**决策原因**：项目经历是简历核心，需要突出个人贡献和技术能力

---

### 校园经历 (campus)

**变更**：要求 STAR 法则 + 量化（如活动参与人数、覆盖范围）

**决策原因**：校园经历容易被忽略，需要具体化成果

---

### 个人优势 (advantage)

**变更**：聚焦用户原始输入，不综合其他模块信息

**Prompt 片段**：
```
请根据用户填写的个人优势，进行优化：
1. 保持原意，不添加用户没有提到的内容
2. 用具体事例来支撑优势描述
```

**决策原因**：
- 用户反馈不希望 AI 添加未提及的内容
- 个人优势应该基于用户真实经历，而非 AI 推断

---

## [v2] 2026-04-07 - 纯净文本输出

### 通用变更

**变更**：移除 Markdown 格式，移除所有符号前缀（`•`, `-`, `*`）

**决策原因**：
- Markdown 格式会导致 `{"content":""}` 嵌套问题（智谱 API 返回格式）
- 用户反馈 `•` 等符号影响观感和复制体验
- 简历内容应该是纯文本，用户可自由编辑

### 教育经历 (education)

**变更**：移除该模块的 AI 生成功能

**决策原因**：
- 教育经历信息结构简单（学校、专业、时间）
- AI 扩写反而容易添加不准确的信息
- 用户只需保留基本信息即可

---

## [v1] 2026-04-07 - 初始版本

### 概述

初始实现，采用 Markdown 格式输出，支持以下模块：
- 教育经历 (education)
- 实习经历 (internship)
- 项目经历 (project)
- 校园经历 (campus)
- 个人优势 (advantage)

### 已知问题

1. Markdown 格式导致输出有 `{"content":""}` 嵌套
2. `•` 符号过多影响阅读
3. 内容过于冗长，用户难以筛选

## 附录：Prompt 优化检查清单

每次修改 Prompt 前，检查以下问题：

- [ ] 输出内容是否有量化数据？
- [ ] 是否符合 STAR 法则？
- [ ] 是否添加了用户未提供的信息？
- [ ] 格式是否便于用户复制使用？
- [ ] 是否会产生 JSON 嵌套问题？
